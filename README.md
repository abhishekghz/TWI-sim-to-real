# Physics-Guided Sim-to-Real Domain Adaptation for Through-Wall Hidden-Target Detection

Extends Yadav et al., *Defence Science Journal* 76(2), 2026.

Real through-wall imaging (TWI) data is expensive to collect, so this project trains a
detector mostly on **physics-based synthetic** data and adapts it to a small set of real
VNA captures. Two things make it work: a stepped-frequency forward model whose wall
parameters are estimated from the real captures (rather than guessed), and a
MUSIC-anchored domain-adversarial network that aligns the synthetic and real features.

---

## 1. Install

```bash
pip install -r requirements.txt
```

Needs Python 3.9+. Everything runs on CPU — a GPU is optional. On Windows use `python`
wherever this guide says `python3`.

---

## 2. Get the synthetic data

```bash
python3 generate_synthetic_dataset.py
```

This loads the real captures, estimates the wall parameters from them with MUSIC, then
generates and **saves to disk** three synthetic sets:

| Set | What it is |
|---|---|
| `synthetic/physics_guided/` | the proposed data — wall parameters estimated from the real captures |
| `synthetic/physics_unguided/` | same forward model, random wall parameters (ablation source) |
| `synthetic/idealized/` | square + Gaussian blobs, no propagation physics (prior approach) |

Each folder gets:

```
images.npy     (800, 28, 48) float32   range-profile patches
labels.npy     (800,)        int64     0 = background/clutter, 1 = hidden target
music.npy      (800, ...)    float32   MUSIC pseudo-spectrum features
metadata.json                          full per-scene provenance: wall params,
                                       target positions, materials
```

It also writes `synthetic/preview/*.png` and `synthetic/DATASET_SUMMARY.json`.

**Look at what you made** — open `synthetic/preview/physics_guided_grid.png` for sample
patches and `synthetic/preview/class_balance.png` for the label split, or print the
shapes and a few metadata records:

```bash
python3 inspect_synthetic.py
```

Prefer already-generated data? The saved `.npy` files are committed to this repo, so you
can skip straight to step 3.

### Optional: see how the synthetic data is built

```bash
python3 visualize_backend.py
```

Writes the intermediate generation stages to `synthetic/backend/` — raw complex S21, the
frequency B-scan, the wall/target physics decomposition, range profiles, and the
assembled-vs-normalized patch — plus a combined storyboard of all stages.

## 3. Get the results

```bash
python3 src/run_experiments.py
```

Trains all five arms plus three ablations with **leave-one-capture-out** validation,
sweeping how much real data is used for fine-tuning (0% → 100%).

> **Before you run this:** `OUT` and `FIG` near the top of `src/run_experiments.py` are
> absolute paths from the original machine. Point them at this repo's `outputs/` and
> `figures/` folders. If you moved the real data, also fix `ROOT` on the line above.

Takes roughly 15–25 min on CPU at the default settings. It checkpoints
`outputs/metrics_partial.json` after each arm, so you can watch progress. Produces:

| Output | Contents |
|---|---|
| `outputs/metrics.json` | every accuracy / precision / recall / F1 number, plus run config |
| `outputs/efficiency_curve.csv` | F1 per arm at each real-data fraction |
| `figures/efficiency_curve.png` | F1 vs fraction of real data used |
| `figures/ablation.png` | contribution of physics guidance and the MUSIC anchor |
| `figures/zeroshot_bars.png` | 0%-real (zero-shot) transfer per arm |

Read the headline numbers back out:

```bash
python3 -c "import json; m=json.load(open('outputs/metrics.json')); [print(k, {f: round(x,3) for f,x in v['f1'].items()}) for k,v in m.items() if k!='meta']"
```

`figures/domain_comparison.png`, `figures/music_anchor.png` and `figures/range_profile.png`
are included as static illustrations; they are not regenerated by the scripts above.

## Expected results

Leave-one-capture-out on the real VNA two-target data:

| Arm | F1 @ 0% real | F1 @ 100% real |
|-----|------:|--------:|
| Real-only baseline | 0.159 | 0.244 |
| Idealized-synthetic (prior) | 0.159 | 0.705 |
| Physics-synthetic (no adaptation) | 0.448 | 0.744 |
| **Proposed (physics + MUSIC-DANN)** | **0.443** | **0.802** |

The trends are the point, not the third decimal place. Idealized synthetic data
transfers no better than nothing at 0% real; adding propagation physics roughly triples
zero-shot F1; the MUSIC anchor adds a further clear gain once real data is mixed in.
Small runs will shift the numbers but should reproduce this ordering.

To reproduce the published values more closely, edit the top of `src/run_experiments.py`:
set `DEV = "cuda"`, raise `N_SYN` to ~1500, and raise the `epochs` in `train_plain` /
`train_dann` to 60 / 80.

## Alternative: train from the saved data

```bash
python3 train_from_saved.py
```

Trains on the `.npy` files written in step 2 instead of regenerating scenes in-process.
Faster to iterate on when you are changing only the model.

## Troubleshooting

- **`.mat not found`** — fix `ROOT` at the top of `src/run_experiments.py` and
  `generate_synthetic_dataset.py` to point at `data/Data two targets`.
- **`synthetic/ not found`** — run step 2 first.
- **Writes land somewhere unexpected** — the `OUT` / `FIG` absolute paths noted in step 3.
- **Too slow** — lower `N_SYN` and the epoch counts, or use a GPU.
- **Real patches all one class** — the labeller keys off the two dominant post-wall
  returns; if you change the wall standoff much, adjust the `post = rng > 0.7` threshold
  in `src/datasets.py::extract_real_patches`.

---

## Higher fidelity

Swap the analytic forward model in `src/synth_twi.py::generate_scene` for a gprMax FDTD
solver behind the same `-> S21 (28, Nf)` interface, raise `N_SYN` and the epoch counts,
and train on GPU.
